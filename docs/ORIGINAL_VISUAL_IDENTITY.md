# Nexora Original Visual Identity Policy

## Product requirement
Every app or website generated by Nexora should receive a project-specific visual identity. Icons and imagery must not be blindly reused across unrelated projects.

## Generation behavior
- Derive a fresh visual concept from the project's audience, purpose, and brand brief.
- Generate original icon silhouettes, compositions, palette, lighting, textures, and image framing.
- Use a per-request creative identifier as a variation cue.
- For icons, prioritize a recognizable silhouette, small-size legibility, balanced negative space, and clean geometry.
- For hero art and illustrations, tailor the subject, crop, composition, and atmosphere to the page and audience.
- Do not copy, trace, or closely imitate existing app icons, logos, branded identities, or reference images.
- Treat Pinterest and other reference galleries as inspiration only. Verify asset-specific rights before reuse.
- If original generation is unavailable, disclose that limitation and use a properly licensed asset or a clearly labeled placeholder rather than claiming a bespoke image was generated.

## Quality and verification
Before release, review each visual for brand fit, clarity at intended sizes, artifacts, accidental text, watermarks, and obvious similarity to known assets. A future asset registry should store project ID, prompt fingerprint, generated asset hash, provider, and license/source metadata so repeated assets can be detected across projects.

## Important implementation note
Prompt-level originality instructions and unique request identifiers encourage distinct results but do not mathematically guarantee uniqueness. Reliable cross-project duplicate prevention requires a persistent asset registry and perceptual-similarity checks.
